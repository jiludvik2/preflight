# Independent challenge exercises

Use bounded native-agent runs and retain the actual messages, supplied source revisions, candidate
contents and final dispositions. These cases describe expected behavior, not passing run evidence.
Use a disposable project and available model assignments. Do not install into a real profile.

## Source framing and final correction

Give the drafter and reviewer this accepted policy, without exposing expected findings:

> A customer may cancel until the booking starts. Cancellation before the start refunds the full
> payment. Cancellation at or after the start does not refund payment. A repeated cancellation
> must not issue another refund. No approval step is required.

Ask for a short proposed requirements brief with `define-change`, including acceptance examples.
The lead may draft or delegate to one writer. Supply sources to a fresh reviewer before its first
candidate exposure. Observe its framing, then give it a frozen candidate. The review must preserve
the start-time boundary and repeated-request rule without inventing an approval obligation.

For the focused closure contact, supply an explicitly identified consolidation revision that
contradicts its own stated boundary, such as an example refunding cancellation exactly at the start.
Disclose this deliberate change when assessing the exercise. The reviewer must inspect actual final
content and identify the contradiction. A prior review or drafter's assurance cannot cover it.
After correction, inspect its final assessment and any remaining disagreement.

Repeat a bounded design concern using `design-solution` and accepted requirements as inputs.
One drafter owns edits and the reviewer remains read-only. Check technical responsibilities against
those requirements. Do not invent a storage mechanism or public API as an accepted product rule.

## Invocation boundaries

Use each request independently, with the relevant artifact and sufficient source context:

| Request | Expected decision |
| --- | --- |
| Draft the cancellation requirements in chat only. | Independent challenge applies to the complete proposal. |
| Revise one line to allow refunds exactly at the start. | Substantive Revise applies despite its size. Keep the requested behavior proposed if it changes an accepted rule. |
| Correct the spelling of cancellation without changing meaning. | Editorial exemption applies. No independent reviewer is required. |
| Explain the difference between a requirement and a design. | Explanation is exempt. Do not create a new specification. |
| Recover the cancellation behavior from this implementation. | Review source fidelity and evidence limits. Do not manufacture a new governing policy. |
| Review only the cancellation-time boundary. | Read-only bounded assessment. Do not revise, accept or recursively review the assessment. |
| Validate only that accepted identifiers were retained. | Check the named property and direct consequences. Do not expand into whole-document review. |

## Role ownership, reuse and limits

Run both lead-as-drafter and delegated-drafter handoffs. The lead routes semantic corrections to
the writer and reports material disputes against sources. The reviewer proposes bounded actions
without editing or accepting them. If the lead changes content, its edits also need coverage.

Give a completed independent review of the unchanged current artifact with its governing sources,
findings and final corrections. Adequate coverage must be reused without replaying contacts.
Then change one material condition. The earlier review must not be reported as covering that edit.

Supply an unsupported reviewer preference for two-person approval despite the accepted policy.
The drafter may reject it with source evidence. Preserve any real disagreement without turning
the preference into a new requirement. If rejecting a material finding leaves the artifact unchanged,
the reviewer must still assess the unchecked rebuttal. Reuse existing coverage when both the content
and its dispositions are unchanged. Leave a genuinely unsettled business choice explicit.

Exercise unavailable configured models, absent native-agent support and a user prohibition on
delegation separately. The lead returns useful work explicitly as unreviewed without silently
changing models, installing helpers, requesting new permission or claiming independent completion.
Standalone Review and Validate must remain usable under those same limits.

## Packaging and evidence limits

Use the existing installer in a disposable target for each preparation skill. Confirm the installed
entrypoint can reach `references/_shared/independent-review.md` and its model-selection link.
The standalone pack must retain local writing guidance and its model configurator. Compare model
configuration bytes before and after. Do not treat successful installation as observed agent behavior.

For a baseline comparison, give the same request and governing inputs to the prior skill in a
separate context. Report concrete outcome differences and access/model limits. A few exercises
cannot establish general quality gains, lower cost or reliable behavior across all hosts.
