# Model selection and consistency exercises

Use bounded actors with accepted source material. These are expected decisions, not passing
runtime evidence. Keep grader expectations outside the actor's inputs.

## Select views without a diagram request

Draft requirements containing interacting eligibility conditions, ordered handoffs and distinct
context meanings. Include the smallest set of useful views from the content without requiring a
diagram request. Preserve privacy, decision ownership and the difference between missing and
negative information. A simple isolated threshold may need only a boundary example.

Draft a technical design with runtime placement, interacting conditions and deadlines. Select
material deployment, decision or timing views without requiring every diagram type. Preserve
adequate reused models and their level of detail.

## Model state-dependent behavior with Mermaid

Use an accepted lifecycle where the same event has different effects in different states.
Select a Mermaid state-transition view during Draft or substantive Revise. Preserve states,
events, guards, effects, repeated events and terminal behavior. Use hierarchy or concurrent regions
only when supported. Do not invoke a personal skill, install tools or run formal checks.

An omitted transition is not proof of prohibition. A diagram that renders is not proof of source
fidelity or exhaustive invariant checking. Report unavailable syntax, rendering and viewer checks.

## Validate consistency without editing

Supply requirements and a proposed design that contradict a time boundary, conflate two context
meanings or disclose prohibited information. Identify the mismatches with source locations and
revealing cases. Accept justified refinements and different notation. Keep validation scoped and
read-only; do not generate a replacement design or require a comparison ledger.

## Preserve standalone behavior

Use only the installed public snapshot. Both skills retain local writing, model routing,
environment configuration and independent-challenge guidance. Absence of a renderer or reviewer
must be reported rather than hidden. Verify snapshots retain required references and that model
configuration and other public-only helpers are unchanged.
