# Requirement-boundary review cases

Exercise define-change in read-only Review mode with these proposed rules and only the public
package. Keep expected findings below out of the acting agent's request.

## Input

- REQ-001: The export service generates the requested CSV and records the export in the audit log.
- REQ-002: Before resuming a blocked implementation portion, the caller checks that the answer
  resolves its dependency against current inputs and has the acceptance required for that portion.

| Role | Required responsibility |
| --- | --- |
| Operator | Accepts an export configuration before its operational use. |

## Expected behaviour

The review exposes the independently assessable CSV and audit outcomes, using a case where one
succeeds and the other fails. It examines the normative table and reports missing ownership
rather than assigning its obligation to an arbitrary nearby requirement. It retains current
answer and acceptance as joint conditions of one resumption gate. Its compact obligation map
makes the examined coverage and boundary decisions visible in the existing review result.
A single clear obligation needs no invented split, new ledger or target number of requirements.

Report permission, source and checking limits. Read-only review must not revise or accept the
proposals, start implementation or require a private helper. These cases are exercise inputs
and assessment guidance, not evidence that an agent has run them or a replacement for package tests.
